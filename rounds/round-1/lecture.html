Loops Explaining Loops

A 10-minute page about agentic loops — written, in part, by one.

What is an agentic loop?

Normally, when you use an AI chatbot, it's one question, one answer. You ask, it replies, done. An agentic loop is different: instead of answering once, the AI repeats a cycle of reasoning and acting — over and over — until some goal is met or it runs out of budget.

The cycle usually looks like this: the AI thinks about what to do next, takes an action (like running code, searching the web, or editing a file), looks at the result, and decides whether it's done or needs another pass. This pattern has a name in AI research — ReAct (short for "Reason + Act") — from a 2022 paper by Google researchers, and it's the basic skeleton underneath most AI agents built since.

Reason
"what should I do?"
→
Act
run code, search, edit
→
Observe
check the result
→
Repeat or Stop

The loop needs a stopping condition — a rule for when to quit. Common ones: the goal is achieved (tests pass, the task is done), a maximum number of steps is hit, or a human interrupts it. Without a stopping condition, a loop can run forever, which is exactly the kind of thing that goes wrong in practice (more on that later).

When should you use one?

Not every task needs a loop. If a task is one step — summarize this paragraph, translate this sentence — a single AI call is faster, cheaper, and just as good. Loops earn their cost when a task is multi-step and the right next step depends on what happened in the previous one.

A good rule of thumb: use an agentic loop when the task has a way to check its own progress — a test suite that passes or fails, a compiler that errors or doesn't, a checklist that's either complete or not. That gives the loop something concrete to react to at each step. Tasks with no clear "am I done yet?" signal are much harder to hand to a loop, because it has no way to know when to stop trying — which is a large part of why this very experiment (see below) had to define an explicit scoring rule up front, instead of just letting the AI decide when the page "felt" finished.

Pros and cons

Pros

  • Handles multi-step work. A loop can plan, act, check, and correct itself across many steps without a human re-prompting it each time.
  • Self-correction. If step 3 reveals that step 1 was wrong, the loop can notice and fix it on step 4, instead of a human catching it later.
  • Takes real actions. It can call tools that actually change something — run code, query a database, send a file — not just produce text.

Cons

  • Slower and more expensive. A single AI reply might take a second. A loop chains many replies together, so a task can take minutes and cost far more.
  • Can spiral. Researchers have documented "hallucination spirals," where a coding agent's small early mistake compounds over several loop iterations into a much bigger, self-reinforcing failure.
  • Hard to grade its own work. If the AI itself is also checking whether it's done, it can be too easy on itself — a documented pattern researchers call self-attribution bias. That's a real risk for exactly this kind of project.

The example is this page

This lecture page is itself the output of an agentic loop. An AI played two roles across several rounds: a Builder, who wrote or revised the page, and a Critic, who scored the current draft and pointed out specific problems. Each round, the Builder responded to the Critic's actual feedback, and the loop kept going until the draft hit a strict score on both content and design, or a fixed round limit was reached — whichever came first.

That's the "am I done yet?" signal from the previous section, made concrete: a numeric rubric instead of a vague feeling of "looks good." If you want to see the whole process — every draft, every critique, and how the scores actually moved round to round — that's in the companion file that came with this page.

Recap

An agentic loop is a repeating reason-act-observe cycle an AI runs until a stopping condition is met. Use one when a task is multi-step and has a checkable definition of "done." The upside is autonomy and self-correction across many steps; the downside is cost, latency, and the risk of the loop spiraling or grading its own homework too kindly.
